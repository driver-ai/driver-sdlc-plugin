# Changelog

All notable changes to the Driver SDLC Plugin (drvr) will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.2.0] - 2026-07-16

### Added

- **Codex**: Native `.codex-plugin/plugin.json` manifest with Driver MCP configuration and install-surface metadata
- **Codex**: `drvr` compatibility skill that routes existing command workflows and translates agent delegation for Codex
- **Codex**: `AGENTS.md` projects template for native repository instructions
- **Tests**: Structural coverage for the Codex manifest, workflow router, marketplace policy, and project template

### Changed

- **Research**: Codebase standards discovery now supports both `AGENTS.md` and `CLAUDE.md`
- **Marketplace**: Added Codex-compatible display metadata and installation policy
- **Documentation**: Added Codex installation, invocation, and platform-specific hook guidance

## [1.1.0] - 2026-05-14

### Added

- **Skills**: `intent-guidance` — mines the author's tacit knowledge at feature start, producing `research/00-intent.md` before codebase research begins
- **Commands**: `/drvr:open-pr` — create a pull request from handoff documentation generated by `/drvr:docs-artifacts`
- **Commands**: `/drvr:review` — run internal standards review before PR, check code against standards and plan criteria, auto-fix violations
- **Commands**: `/drvr:driverize` — install Driver enforcement stack (hooks, shadow agents, context injection, CLAUDE.md routing)
- **Commands**: `/drvr:un-driverize` — remove Driver enforcement stack, restore backups and remove artifacts
- **Agents**: `standards-review` — review code changes against codebase standards, plan acceptance criteria, and test coverage
- **Planning**: Environment section with Base Branch / Feature Branch model across entire SDLC pipeline
- **Planning**: Step 4.5 confirmation checkpoint before implementation begins
- **Implementation**: Worktree isolation support for parallel execution of independent tasks
- **Implementation**: Transition advisory checks for open questions at phase boundaries
- **Implementation**: Cross-feature dependency discovery and registry for overlapping file targets
- **Research**: Decision tracking via append-only DECISIONS.md artifact with DEC-NNN entries
- **Infrastructure**: Interactive project context Q&A in `/drvr:feature`
- **Infrastructure**: Three-layer state commit strategy for SDLC artifacts
- **Infrastructure**: Driverize v1.1 with conditional enforcement, Agent unlock, event-type aware hooks
- **Infrastructure**: Post-PR lifecycle phases (PR Review, Revision, Merge, Verification, Shipped)

### Changed

- **Planning**: Plans now require Environment section with codebase path, branches, test command, and standards doc
- **Implementation**: Base Branch / Feature Branch awareness across the entire pipeline
- **Infrastructure**: Plugin version bumped from 1.0.0 to 1.1.0

## [1.0.0] - 2026-04-17

### Added

- **Skills**: `research-guidance` — structured Why-What-How methodology, document organization, completion criteria
- **Skills**: `planning-guidance` — TDD-first task design, test strategy, architecture fit, task breakdown
- **Skills**: `implementation-guidance` — plan-driven task execution, deviation tracking, commit discipline
- **Skills**: `materialize-tasks` — convert approved plan tasks into standalone task docs for sub-agent execution
- **Skills**: `sdlc-orchestration` — lifecycle coordination, phase transitions, session resumption, bookkeeping
- **Commands**: `/drvr:setup` — set up a projects directory with MCP configuration, structure, and connectivity verification
- **Commands**: `/drvr:feature` — scaffold a new feature project with FEATURE_LOG.md and research structure
- **Commands**: `/drvr:orchestrate` — resume work on a feature, read the feature log, report state, suggest next action
- **Commands**: `/drvr:dry-run-plan` — walk through a plan as-if implementing to identify gaps before real implementation
- **Commands**: `/drvr:assess` — curate the test suite after implementation, categorize, prune scaffolding, promote valuable tests
- **Commands**: `/drvr:docs-artifacts` — generate handoff documentation (overview, architecture, testing guide, risks)
- **Commands**: `/drvr:context` — gather codebase context for a specific task via Driver MCP
- **Commands**: `/drvr:retro` — analyze current session, evaluate work quality, identify improvements
- **Agents**: `driver-task-context` — gather targeted codebase context from Driver MCP in isolated sandbox
- **Agents**: `handoff-analyzer` — orchestrate handoff documentation generation, coordinate extraction agents
- **Agents**: `commit-log` — extract detailed commit history for a feature branch
- **Agents**: `decisions-log` — extract design decisions from research docs and plans in ADR format
- **Agents**: `features-list` — catalog all capabilities added in a feature branch
- **Agents**: `security-review` — analyze code changes for security concerns
- **Agents**: `test-coverage` — map tests to implementation, identify coverage gaps
- **Agents**: `dependency-analysis` — review dependency changes, license compliance, known vulnerabilities
- **Agents**: `cascade-check` — check whether implementation deviations cascade to downstream plans
- **Hooks**: `laziness-detector` (PreToolUse) — block Write/Edit operations containing lazy code patterns
- **Hooks**: `track-skill-load` (PreToolUse) — track which skills are loaded during a session
- **Hooks**: `commit-artifacts` (SessionEnd) — auto-commit SDLC artifacts at session end
- **Infrastructure**: Core SDLC lifecycle (Research → Planning → Validation → Materialization → Implementation → Review → Bookkeeping → Assessment → Handoff)
- **Infrastructure**: Standards enforcement pipeline (discovery → planning constraints → implementation checks → assessment review)
- **Infrastructure**: Template versioning for progressive CLAUDE.md updates
- **Infrastructure**: Plan concreteness with Data Structures & Callables and inline snippets
